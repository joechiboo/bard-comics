## 通用原則

### Prompt 撰寫

- **顏色詞在黑白畫風下不可靠**：style_suffix 是黑白墨線風，生圖模型常直接忽略顏色描述（見 1-1 案例：grey cat 生成全黑貓）。若顏色是劇情辨識重點，改用**明暗與材質**描述（如 `light-furred` / `pale`），或乾脆放棄顏色改用形狀特徵。
- **角色 token 要靠近主詞**：token（獨眼、白瞳、裂嘴笑）放在該角色描述的緊鄰位置，不要堆在句尾，多人同格時才不會張冠李戴。⏳ 待驗證（1-1 多為單人特寫，1-3 女巫同框再確認）
- **一格一個視覺焦點**：prompt 塞太多主體時，模型會自己挑一個畫，其他的變背景雜訊。想要的東西只有一件就只寫一件。⏳ 待驗證

### 快取與重生

- 快取鍵 = provider + 尺寸/比例 + prompt 全文的雜湊：**prompt 改一個字就整格重生**，校稿時確定要改再改。
- 只改 `dialogue`/`quote` 不動 `prompt` → 零生圖成本，排版問題盡量往對白/排版端解。
- pollinations 的 seed 固定 42：同 prompt 必得同圖。想要「同 prompt 換一張」，得改 prompt（加無害的措辭變化）。

### 供應商特性（pollinations / flux）

- 黑白墨線 style_suffix 吃得很穩，五頁下來調性一致，氣氛掌握（荒原、閃電、剪影）是強項。
- 弱項預期在**角色跨格一致性**與**多人互動構圖**；首輪 1-1 單人特寫多、還看不出來，1-2 / 1-3 出圖後回來補記。
- 免費服務尖峰時慢，429/5xx 靠腳本內建退避重試，掛掉重跑即可（有快取不浪費）。

## 排版端待改（不是 prompt 的鍋，別浪費重生額度）

- 音效目前和對白共用白底圓角框，「音效感」偏弱 → 之後改成畫在圖上的描邊大字（pipeline backlog，同 README 氣泡尾巴一項）。
